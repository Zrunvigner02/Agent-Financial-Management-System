# 意图分流规则（业务 vs 工程）

> 2026-11-19 用户确认：**查询/录入数据一律交给财务系统智能体；改代码/加功能由本地开发助理做。**
> 实现：`backend/intent-router.mjs`（纯规则，零 token）；自测 `node tools/test-intent-router.mjs`。

## 一、三类意图

| 类型 | 命中特征（举例） | 执行方 | 动作 |
| --- | --- | --- | --- |
| **业务 finance** | 查 / 统计 / 汇总 / 报表 / 利润 / 余额 / 凭证 / 分录 / 科目 / 发票 / 税额 / 订单 / 发货 / 固定支出 / 工资 / 房租 / 应收应付 / 导入 / 录入 / 记账 / 对账 / 渠道 / SKU | **财务系统智能体** | 调本地 MCP 工具或 `/api/*`，返回结论与数字 |
| **工程 dev** | 改代码 / 加功能 / 加按钮 / 改样式 / 调整菜单 / 排序筛选 / 报错 / 白屏 / bug / 部署 / 打包 / 版本 / 规则模板口径变更 | **本地开发助理** | 改文件、跑检查、写 CHANGELOG、推送 |
| **其他 other** | 寒暄（你好 / 谢谢）、指令不明 | 当前会话 | 简短回应 + 一句追问，不猜 |

**冲突时以工程类优先**：例如「给报表加一列备注」命中"报表"但也命中"加一列"，按 **dev** 处理。

## 二、业务类：只互通，不重写

- 一律走本地财务系统的 MCP 工具（`zhuangdian-finance`）或 `/api/*` 接口
- **不允许**在对话里手写 SQL 重算口径；报表格式以 `rules/report-rules.md` 为准
- 写操作（建凭证、改订单、录固定支出）先出摘要等确认，不擅自落库
- 查不到就如实说"没有该数据"，不要编造数字

## 三、工程类：由本地助理执行

- 改前先读 `README.md` / `rules/`；改后跑 `npm run check`
- 前端为注入式脚本（`upstream/*.js`），**不改编译产物**
- 每次改动更新 `CHANGELOG.md` 与版本号；影响面大时同步 README

## 四、回复长短

业务问答从简、工程说明从详，细则见 `rules/agent-reply-style.md`：非开发问答 1~3 句给结论、要点不超 5 条；报数字带期间与口径；缺数据直接说缺哪份。

## 五、企微 A 方案下的补充

- 通道不透传 userid：靠「姓名：」署名或文件名带姓名做归属（见 `rules/wecom-reply-rules.md`）
- 纯文字问题简短回答（1–2 句）；带附件先给结论 + 关键数字
- 未识别归属时不要猜姓名；需要确认只问一句「请问是哪位？」
