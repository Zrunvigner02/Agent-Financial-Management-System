# 财务端销售损益表核算规则（锁死版）

> 本文件是「财务端销售损益表」的唯一口径依据。代码实现：`backend/finance.mjs`、`tools/finance-pnl.mjs`。
> 改口径必须先改这里，再改代码。

---

## 0. 先分清两个部门维度（最容易混的地方）

| 维度 | 谁在用 | 统计什么 | 落地表 | 口径标识 |
| --- | --- | --- | --- | --- |
| **销售端** | 销售部 / 运营 | 各平台**卖了多少钱**（GMV、退款、推广费、店铺日报） | `sales_daily` | `sales_dept` / `platform` / `wecom` |
| **财务端** | 财务部 | **赚了多少钱**（收入、成本、毛利、边界利润、净利润） | `fin_pnl_lines` | 独立，无 source 字段 |

**两条链路互不覆盖、互不混算、不做自动换算。** 销售端的企微日报入库（`wecom` 口径）只服务于销售端统计；
财务端损益表的收入一律取旺店通发货数据与平台账单，不得直接拿销售端 GMV 当收入。

---

## 1. 核算逻辑（链条固定，不可跳步）

```
收入（去退后） − 成本 = 毛利
毛利 ÷ 收入 = 毛利率

毛利 − 推广费 − 平台扣点 − 物流费 − 其他直接支出 = 边界利润
（以上四项合称「变动费用合计」）

边界利润 − 人力成本（小销售直接人力成本 + 固定公摊人力成本）= 净利润
净利润 ÷ 收入 = 净利率
```

**比率的分母一律是「收入」**，不是 GMV、不是收入总额。负数比率照实输出，不取绝对值。

### 与现有 Excel 模板的命名对照

模板 `2026.10销售损益表-多品牌（月度测算）.xlsx` 用的是另一套叫法，两者必须能对上：

| 本文件口径 | 模板行名 | 说明 |
| --- | --- | --- |
| 主营业务收入（去退后） | 主营业务收入 | 模板 Sheet2「去退后收入」 |
| 毛利 | 毛利 | — |
| 变动费用合计 | 变动费用合计 | 推广费+平台扣点+物流费+其他直接支出 |
| 边界利润 | 边界利润 | — |
| 人力成本 | **固定费用合计** | 模板把人力成本整体叫「固定费用」 |
| 净利润 | **经营利润** | 模板把扣完人力后的利润叫「经营利润」 |
| 净利率 | 经营利润的比率列 | — |

> 对外汇报用老板口径（净利润 / 净利率）；导出对齐模板时映射成「固定费用合计 / 经营利润」。

## 2. 科目清单（`fin_pnl_lines.item`）

基础科目（只有这些入库，派生一律算出来）：

| item | 中文 | 取数来源 |
| --- | --- | --- |
| `revenue_gross` | 收入总额 | 旺店通发货数据 |
| `refund` | 退款金额 | 旺店通发货数据 |
| `revenue` | 主营业务收入（去退后） | 收入总额 − 退款 |
| `cost` | 成本 | 旺店通成本金额 / 采购成本表 |
| `ad_spend` | 推广费 | 天猫万相台 / 抖音巨量千川 / 小红书千帆 / 京东京准通 |
| `platform_fee` | 平台扣点 | 天猫支付宝账单 / 抖音资金账单 / 小红书结算账单 / 京东自营月度结算返利 |
| `logistics` | 物流费 | 旺店通物流费（跨境品牌含关税时记 `含关税` 备注） |
| `other_direct` | 其他直接支出 | 手工录入，需写明事由 |
| `labor_direct` | 直接人力成本 | 人事部工资表（小销售口径） |
| `labor_shared` | 公摊人力成本 | 人事部公摊费用表 |
| `labor` | 人力成本（未拆分） | 仅当只有总额时使用，会标记「未拆分」 |

派生科目（不入库，实时算）：`毛利`、`毛利率`、`变动费用合计`、`边界利润`、`净利润`、`净利率`。

## 3. 取数来源与颗粒度

| 数据 | 来源 | 颗粒度 | 现状 |
| --- | --- | --- | --- |
| 收入 / 退款 / 成本 / 物流费 / 单品 | 旺店通 ERP 发货数据 | 日 / 月 | **未接入**（无接口、无导出样例） |
| 推广费 | 万相台 / 千川 / 千帆 / 京准通 | 日 / 月 / 季 | **未接入** |
| 平台扣点 | 支付宝账单 / 资金账单 / 结算账单 / 京东结算返利 | 月（按订单汇总） | **未接入** |
| 人力成本 | 人事部工资表 + 公摊表 | 月 | 工资表在企微缓存里可解析，公摊表未见 |
| 历史样例 | `2026.10销售损益表-多品牌（月度测算）.xlsx` | 月 | **可导入，作为验证基准** |

## 4. 比例型科目的处理（不许混进实际数）

模板里平台扣点直接按收入 ×5%、物流费按 ×3%（跨境品牌 ×13.1%=9.1%关税+4%物流）估算。
这类**估算值必须标 `basis='估算'`**，与 `basis='账单'` 的实际值分开存，
报表输出时若同一科目同时存在实际与估算，**以实际为准并提示差异**，不得加权平均。

---

## 5. 禁止事项

- ❌ 不要把销售端 GMV 当成财务端收入（两者差退款、差发货口径、差时点）
- ❌ 不要用毛利率倒推成本，也不要给未知成本填 0
- ❌ 不要把「边界利润」叫成「净利润」（中间还差人力成本）
- ❌ 不要用未来月份或缺失月份输出 −100% 之类的假比率，缺数据就留空
- ❌ 不要跨品牌合并后再算比率（必须先按渠道算，再汇总；比率由汇总后的金额重算）
