# 报表生成规则（锁死版）

> 本文件是**销售端**「销售报表」的唯一版式与口径依据。任何人（含 AI）改报表前必须先读这里；
> 与本文冲突的改动一律视为错误。代码实现：`tools/make-sales-report.mjs`。
>
> **财务端**（收入−成本−费用−人力＝净利润）是另一套口径，见 `rules/finance-pnl-rules.md`，
> 两套口径互不覆盖，不要把销售端 GMV 当财务端收入。
>
> **版式标准（v2.3.0）**：`rules/report-template/标准样板_月对比表-日报汇总26年11月7日.xlsx`。
> 生成器直接复用该样板的 `styles.xml` 与 `theme1.xml`，样式从此不必手写；改动版式必须先改样板或经确认。

---

## 1. 数据来源与口径隔离

销售数据按来源分三种口径，**互不覆盖、互不混算**：

| 口径 | `sales_daily.source` | 说明 |
| --- | --- | --- |
| 平台口径 | `platform` | 天猫、京东、拼多多、小红书等平台后台或日报导出 |
| 销售部口径 | `sales_dept` | 销售部人工报送 |
| 财务口径（旺店通） | `wdt` | 旺店通等 ERP 取数，按发货/实收核算 |
| 企微缓存口径 | `wecom` | 企微 PC 端缓存里的日报文件自动解析入库（v1.9.0 起，独立口径） |

> `wecom` 口径由 `backend/wecom.mjs` 写入，来源是企微本地缓存的日报附件，不是平台后台直连；
> 与 `platform` 口径**不得互相覆盖**，两者对账时差异属正常（取数时点与口径不同）。

报表默认输出**平台口径**；需要对比时用 `/api/enterprise/sales/compare`，不得把两套数合并成一套。

## 2. 品牌归并

- 歌剧魅影 = **歌剧**
- drhauschka / 德国世家 / 世家 / DH = **世家**（报表列名用「世家」，对外可说 DH）
- PF79 = **PF**
- 识别方式：按店铺名关键字归并（`BRAND()`）；未识别出的品牌**自动新增一块**，不丢弃、不并入其他品牌。
- 品牌顺序：歌剧 → PF → DH → 其他（新品牌按名称排序追加）。

## 3. 工作表结构（五张，顺序固定）

> **v2.3.0 起，版式以样板文件为准**：`rules/report-template/标准样板_月对比表-日报汇总26年11月7日.xlsx`
> （老板提供，已固化入库，不得删改）。
>
> 实际输出 **10 张表**，字体/边框/填充/列宽/合并/表头层级全部**直接复用样板自带的 styles.xml 与 theme1.xml**：
>
> `总月报表{年}年{月}月` · `歌剧月对比表` · `歌剧日汇总` · `歌剧主打单品分析`
> · `PF月对比表` · `PF日汇总` · `PF主打单品分析`
> · `世家月对比表` · `世家日汇总` · `世家主打单品分析`（世家这 3 张按同样式追加，样板本身只做到歌剧与 PF）
>
> 与本样板冲突时：**版式以样板为准，口径（收入/成本/比率定义）以本文件第 4 节为准**。
> 下方 3.1–3.3 为早期 5 表版本的文字描述，仅作历史参考。

### 3.1 总月对比表

```
行1：A1 标题「总月对比表」（合并 A1:O1，加粗居中）
行2：C 销售数量(合并 C:D) · E 销售额(合并 E:F) · G 退货(合并 G:H) · I 退货金额(合并 I:J)
行3：A 品牌 · C 销售数量 · D 增长比 · E 销售额 · F 增长比 · G 退货数量 · H 增长比
      · I 退货金额 · J 增长比 · K 毛利润 · L 毛利率 · M 销售净利额 · N 销售净利率 · O 总结
行4起：每个品牌一块（品牌顺序：歌剧 → PF → 世家 → 其他）
       第一块：A2 写品牌名，纵向合并覆盖表头两行 + 12 个月 + 小计
       后续块：A 列在首月行写品牌名，纵向合并覆盖 12 个月 + 小计
       B 列 1月…12月（固定 12 行，缺数据留空，不允许删行）
       每块末尾一行「小计」（黄底加粗）
全表最后一行：「总计」——所有品牌整年合计（数量/销售额/退货/净利/净利率），黄底加粗
```

### 3.2 品牌月对比表（歌剧 / PF / DH 各一张）

```
行1：A1 标题（合并 A1:N1）
行2：B 销售数量(合并 B:C) · D 销售额(合并 D:E) · F 退货(合并 F:G) · H 退货金额(合并 H:I)
行3：A 空 · B 销售数量 · C 增长比 · D 销售额 · E 增长比 · F 退货数量 · G 增长比
      · H 退货金额 · I 增长比 · J 毛利润 · K 毛利率 · L 销售净利额 · M 销售净利率 · N 总结
行4–15：1月…12月
行16：总计（黄底）
```

### 3.3 日汇总表

```
行1：A1 标题（合并到最后一列）
行2：每天一个日期标签，跨 4 列合并（B=1日 跨 B:E，F=2日 跨 F:I，J=3日 跨 J:M …）
行3：每天 4 列子表头：销售数量 / 销售额 / 费比 / 毛利率
行4起：渠道行（天猫 / 抖音 / 小红书 / 京东 / 拼多多 / 分销，按此优先级排序）
末行：总计（黄底）
```

## 4. 指标计算口径

| 指标 | 公式 | 备注 |
| --- | --- | --- |
| 销售额 | Σ 平台成交额 | 平台口径原值 |
| 退货金额 | Σ 退款金额 | — |
| 去退成交额 | 销售额 − 退货金额 | 中间值，不单独成列 |
| 毛利润 | 去退成交额 − 成本 | **平台文件无成本时留空，不填 0** |
| 毛利率 | 毛利润 ÷ 销售额 | 毛利为空时同样留空 |
| 销售净利额 | 去退成交额 − 推广费 | 平台文件里的站内推广费/消耗金额 |
| 销售净利率 | 销售净利额 ÷ 销售额 | — |
| 费比 | 推广费 ÷ 销售额 | 仅日汇总表使用 |
| 增长比 | 本月 ÷ 上月 − 1 | **环比**；上月无数据时留空，不写 0 或 −100% |
| 销售数量 | Σ 件数 | 源文件无件数时留空，不用金额估算 |

## 5. 格式规范（视觉锁死）

- 金额：`#,##0.00`（两位小数、千分位）
- 比率：`0.0%`（增长比、毛利率、净利率、费比）
- 全部单元格：细边框（`#BFBFBF`）
- 表头：灰底（`#F2F2F2`）、加粗、居中、自动换行
- 小计 / 总计行：浅黄底（`#FFF2CC`）、加粗
- 品牌列：加粗、水平+垂直居中
- 列宽固定（见代码 `widths`），不得随意压缩导致文字换行错位
- 无数据品牌：保留 12 个月结构，只让数值与小计留空

## 6. 生成与校验

```bash
npm run sales:import                 # 导入平台文件到 sales_daily（platform 口径）
npm run sales:report                 # 输出 exports/销售报表_<期间>_平台口径.xlsx
npm run sales:report -- 2026-11      # 指定期间
```

**验收清单（每次改报表都要过一遍）**

1. 五张表齐全、名称一致、顺序一致
2. 总表 A1 标题存在；A2 起为第一个品牌；每块 12 个月 + 小计；**末尾必须有「总计」行**
3. 列位与本文第 3 节完全一致（可用 `python` 读 xlsx 核对单元格字母）
4. 金额两位小数、比率为百分比；小计黄底
5. 无数据品牌不出现 0.00
6. 与样板文件 `AI；月对比表-日报汇总26年11月7日.xlsx` 并排比对，列不错位

## 7. 禁止事项

- ❌ 不要为了「好看」调整列顺序或增删列
- ❌ 不要把毛利/毛利率用 0 或 100% 填充未知成本
- ❌ 不要把销售部口径与旺店通口径混算
- ❌ 不要删掉无数据品牌的 12 个月行
- ❌ 不要用「未来月份」输出 −100% 之类的假增长比
